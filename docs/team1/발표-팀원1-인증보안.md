# 고객 로그인 인증·보안 설명

고객 로그인의 인증과 보안은 **Spring Security**로 처리합니다. 고객 쪽에서는 다음 6가지를 처리합니다.

- 폼 로그인과 BCrypt 비밀번호 검증
- 비밀번호 5회 오류 시 계정 잠금
- 정지·탈퇴 계정 차단
- 임시 비밀번호로 로그인하면 비밀번호 변경 강제
- URL별 접근 권한
- CSRF 보호

아래에 설정 파일부터 화면까지 계층 순서로 정리했습니다. 경로는 `project/onbank/` 기준입니다.

## 2. SecurityConfig: 보안 설정의 중심

[SecurityConfig.java](../project/onbank/src/main/java/org/doit/onbank/config/SecurityConfig.java)

### (1) 비밀번호 암호화
```java
@Bean PasswordEncoder passwordEncoder() { return new BCryptPasswordEncoder(); }
```
- 가입할 때 비밀번호를 BCrypt 해시로 바꿔 저장합니다 ([MemberService.java:42](../project/onbank/src/main/java/org/doit/onbank/member/service/MemberService.java#L42)).
- 로그인할 때는 Spring Security가 이 인코더로 입력값과 DB 해시를 비교합니다.
- DB 컬럼은 `members.password VARCHAR(100) COMMENT 'BCrypt 해시'`입니다.

### (2) 필터 체인 3개로 영역 분리
| 순서 | 체인 | 적용 범위 | 사용자 테이블 |
|---|---|---|---|
| `@Order(1)` | adminFilterChain | `/admin/**` | admin |
| `@Order(2)` | employeeFilterChain | `/employee/**` | employee |
| `@Order(3)` | **memberFilterChain** | 나머지 전부 (고객) | members |

- 고객 체인은 기본 세션 키(`SPRING_SECURITY_CONTEXT`)를 씁니다.
- 직원·관리자 체인은 세션 키 이름을 따로 씁니다 (`..._ADMIN`, `..._EMPLOYEE`).
- 그래서 고객으로 로그인한 상태로 관리자 화면에 들어가도 비로그인으로 처리됩니다.

### (3) 고객 체인의 상세 설정 ([SecurityConfig.java:182-226](../project/onbank/src/main/java/org/doit/onbank/config/SecurityConfig.java#L182-L226))
| 설정 | 내용 |
|---|---|
| `.userDetailsService(memberDetailsService)` | 로그인할 때 members 테이블에서 회원을 찾습니다. UserDetailsService Bean이 3개라 직접 지정합니다. |
| `.authorizeHttpRequests` | **URL 권한**입니다. `/signup`, `/password/find`, `/api/phone/**`, `/api/email/**`, `/branches` 등은 `permitAll`입니다. `/mybank/**`는 `hasRole("USER")`, `/loan/apply/**`는 `authenticated()`입니다. 그 외는 현재 `permitAll`이고, TODO로 단계적으로 잠글 예정입니다. |
| `.formLogin` | 화면은 `GET /login`이고, `POST /login`은 Spring Security가 처리합니다. 파라미터는 `loginId`, `password`입니다. |
| `.successHandler(LoginSuccessHandler)` | 실패 횟수를 초기화합니다. 그다음 로그인 전에 보려던 페이지로, 없으면 `/`로 보냅니다. 임시 비밀번호로 로그인했으면 변경 화면으로 보냅니다. |
| `.failureHandler(LoginFailureHandler)` | 실패 횟수를 기록합니다. 사유에 따라 `?error`, `?locked`, `?disabled` 중 하나로 보냅니다. |
| `.logout` | `POST /logout`에서 세션을 무효화하고 `JSESSIONID` 쿠키를 삭제한 뒤 `/`로 보냅니다. |
| `.addFilterAfter(TempPasswordFilter)` | 임시 비밀번호 상태에서는 다른 화면을 막습니다. css·js·error는 통과시킵니다. |
| `.exceptionHandling(accessDeniedHandler("/login"))` | CSRF 토큰이 만료되면 403 화면 대신 `/login?expired`로 보냅니다. |
| **CSRF** | 끄지 않습니다. `th:action`을 쓰면 폼에 토큰이 자동으로 들어가고, 로그아웃도 POST만 허용합니다. |

## 3. 인증 처리 클래스 (member/security)

### [MemberDetailsService.java](../project/onbank/src/main/java/org/doit/onbank/member/security/MemberDetailsService.java): `UserDetailsService` 구현
- `POST /login` 요청이 오면 Spring Security가 `loadUserByUsername(loginId)`를 호출합니다.
- members 테이블에서 회원을 찾아 `LoginMember`로 감싸 돌려줍니다.
- 아이디가 없으면 `UsernameNotFoundException`을 던집니다. Spring이 이를 `BadCredentialsException`으로 바꾸기 때문에, 화면에는 "아이디 또는 비밀번호가 올바르지 않습니다"로만 나옵니다. **아이디가 존재하는지 노출하지 않기 위해서입니다.**

### [LoginMember.java](../project/onbank/src/main/java/org/doit/onbank/member/security/LoginMember.java): 세션에 저장되는 로그인 정보
- `UserDetails`, `CredentialsContainer`, `TempPasswordUser`를 구현합니다.
- Member 엔티티를 세션에 그대로 두지 않고 필요한 값만 복사합니다: memberId, loginId, name, 잠금·활성·임시비번 여부.
- `getAuthorities()`는 `ROLE_USER`를 돌려주며, `/mybank/**`의 `hasRole("USER")` 검사에 쓰입니다.
- `isAccountNonLocked()`가 false이면 Spring이 `LockedException`을 던집니다. 대상은 status가 LOCKED인 회원입니다.
- `isEnabled()`가 false이면 Spring이 `DisabledException`을 던집니다. 대상은 SUSPENDED, WITHDRAWN 회원입니다.
- 잠금·정지 검사는 **비밀번호를 확인하기 전에** 이루어집니다.
- `eraseCredentials()`는 로그인에 성공한 뒤 비밀번호 해시를 null로 지워서 세션에 남지 않게 합니다.
- 다른 컨트롤러에서는 `@AuthenticationPrincipal LoginMember me`로 받아 `me.getMemberId()`를 사용합니다.

### [MemberLoginAttemptRecorder.java](../project/onbank/src/main/java/org/doit/onbank/member/security/MemberLoginAttemptRecorder.java): 로그인 결과 기록
- 공통 인터페이스 [LoginAttemptRecorder](../project/onbank/src/main/java/org/doit/onbank/common/security/LoginAttemptRecorder.java)를 구현하며, `MAX_FAIL_COUNT = 5`입니다.
- 실패하면 `member.recordLoginFailure()`를 호출합니다. `login_fail_count`가 1 늘어나고, 5회가 되면 `status = LOCKED`, `login_locked_at`이 기록됩니다 ([Member.java:105-117](../project/onbank/src/main/java/org/doit/onbank/member/entity/Member.java#L105-L117)).
- 성공하면 `recordLoginSuccess()`로 실패 횟수를 0으로 되돌립니다.

**비밀번호 찾기** ([MemberPasswordService.java:32](../project/onbank/src/main/java/org/doit/onbank/member/service/MemberPasswordService.java#L32))
- 아이디·이름·생년월일·이메일이 모두 맞아야 임시 비밀번호를 발급합니다.
- 발급하면 BCrypt로 저장하고, `temp_pw_yn='Y'`를 표시하고, 잠금을 해제한 뒤 메일을 보냅니다.

**비밀번호 변경** ([MyPageController.changePassword](../project/onbank/src/main/java/org/doit/onbank/member/controller/MyPageController.java))
- 현재 비밀번호를 확인하고, 새 비밀번호가 현재 비밀번호와 같으면 거부합니다.
- 변경에 성공하면 **강제로 로그아웃**한 뒤 `/login?changed`로 보냅니다.
- 세션에 남아 있는 임시 비밀번호 표시를 없애려고 다시 로그인하게 하는 것입니다.

## 8. 전체 흐름 요약

```
POST /login (loginId, password, _csrf)
 └ CsrfFilter : 토큰 검사 (불일치 → /login?expired)
 └ UsernamePasswordAuthenticationFilter
     └ MemberDetailsService.loadUserByUsername → LoginMember
     └ 잠금 확인(isAccountNonLocked) / 활성 확인(isEnabled)   ← 비밀번호 확인 전에 차단
     └ BCryptPasswordEncoder.matches(입력값, DB 해시)
         ├ 성공 → LoginSuccessHandler : 실패 횟수 0, 세션 저장, eraseCredentials
         │         └ 임시 비밀번호면 /mybank/profile/password, 아니면 원래 가려던 페이지 또는 /
         └ 실패 → LoginFailureHandler : 실패 횟수 +1 (5회면 LOCKED) → /login?error|locked|disabled
이후 요청
 └ AuthorizationFilter : /mybank/** 는 ROLE_USER 필요 (없으면 /login 으로)
 └ TempPasswordFilter : 임시 비밀번호면 변경 화면 외에는 차단
```

## 9. 고객 쪽에 아직 없는 것

[SecurityConfig.java](../project/onbank/src/main/java/org/doit/onbank/config/SecurityConfig.java)와 [LoginAttemptRecorder.java](../project/onbank/src/main/java/org/doit/onbank/common/security/LoginAttemptRecorder.java) 주석에 "다음 단계"로 적혀 있는 항목들입니다.

- **고객 로그인 이력(`login_log`) 기록:** 관리자 쪽(`admin_login_log`)만 구현되어 있습니다. `MemberLoginAttemptRecorder`는 `recordHistory`를 구현하지 않아서, 기본 메서드(아무것도 하지 않음)가 그대로 쓰입니다.
- **세션 타임아웃과 중복 로그인 제한:** `application.properties`에 세션 관련 설정이 없습니다.
- **URL 권한:** `anyRequest().permitAll()`이 남아 있어서 `/account/**` 같은 화면은 아직 URL 수준에서 막혀 있지 않습니다.

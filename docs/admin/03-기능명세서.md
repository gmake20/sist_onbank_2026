## 작성 규칙

- 기능 ID: `FUNC-ADM-서비스-번호` (요구사항 ID `FR-ADM-서비스-번호`와 번호를 맞춤)
- API 주소, 테이블 컬럼은 초안. ERD·API 명세 확정 시 함께 수정
- "협의" 표시는 다른 파트와 정해야 하는 부분

## 공통 사항

- 화면은 `/admin/**`, fetch로 부르는 데이터 API는 `/admin/api/**` (2026-10-15 변경. 팀원1 `SecurityConfig.java` 56줄의 관리자 체인이 `/admin/**`만 맡기 때문. 예전 `/api/admin/**`는 고객 체인(126줄 `permitAll`)으로 넘어가 로그인 없이 열림)
- 폼 제출 + 화면 다시 그리기로 되는 기능은 API 없이 화면 주소만 쓴다. fetch가 필요한 곳: 대시보드 차트, 실시간 모니터링, 알림 개수 등
- 응답은 팀 공통 응답 형식 사용
- 상태를 바꾸는 기능은 공통 처리 순서를 따른다:
  1. 관리자 권한 확인 → 2. 대상 현재 상태 확인 → 3. 해당 도메인 서비스로 상태 변경 → 4. admin_log 기록 → 5. COMMIT (중간 실패 시 전체 롤백)
- 상태 변경에는 사유 입력이 필수
- 목록 화면은 검색 조건 + 페이징(기본 20건) + 최신순

## 2. 기능 상세

### 2.1 FUNC-ADM-AUT-001 관리자 로그인

| 항목 | 내용 |
|---|---|
| 연결 요구사항 | FR-ADM-AUT-001 |
| 사용자/권한 | 관리자 (비로그인 상태). 직원은 `/employee/login`(사번)으로 따로 로그인 (팀원1) |
| 사전 조건 | 활성 상태 admin 계정 존재 |
| 입력 항목 | 아이디(필수), 비밀번호(필수) |
| 처리 로직 | 1. `AdminDetailsService`가 admin.login_id로 조회 → 2. 상태 확인 (INACTIVE → 사용 불가, LOCKED → 잠금) → 3. 비밀번호 비교 (BCrypt) → 4. 성공 시 관리자 영역 세션 생성, 마지막 로그인 일시 갱신, `admin_login_log` 기록 (temp_pw_yn이 Y면 비밀번호 변경 화면으로 이동) → 5. 실패 시 실패 횟수 증가, 5회면 잠금, `admin_login_log` 기록. 1~3은 팀원1 구현 완료. 4~5의 갱신·잠금·이력 기록·강제 이동은 팀원1 `auth.md` 3장 ⑤⑧ "다음 단계" (관리자까지 하는지 확인 필요) |
| 출력/결과 | 관리자 대시보드로 이동 (임시 비밀번호 상태면 비밀번호 변경 화면) |
| 예외 처리 | 불일치 → "아이디 또는 비밀번호가 올바르지 않습니다" / 비활성·잠금 → "사용할 수 없는 계정입니다" / 고객 계정 입력 → 불일치와 같은 메시지 |
| 사후 조건 | 관리자 세션 생성 |
| 관련 화면 | 관리자 로그인 |
| 관련 API | `POST /admin/login` (Spring Security) |
| 관련 테이블 | admin, admin_login_log |
| 비고 | 직원·관리자 로그인 분리 (2026-10-15, DECISIONS D-02), 세션 방식 (D-05). 로그인 구현은 팀원1 (팀 README 12장). 관리자 파트는 `admin`·`admin_login_log` 테이블과 로그인 이력 조회 화면을 맡는다 |

### 2.2 FUNC-ADM-AUT-003 관리자 권한 접근 제어

| 항목 | 내용 |
|---|---|
| 연결 요구사항 | FR-ADM-AUT-003 |
| 사용자/권한 | 시스템 (모든 요청) |
| 사전 조건 | 없음 |
| 입력 항목 | 요청 URL, 세션 |
| 처리 로직 | 1. `/admin/**` 요청은 관리자 필터 체인이 처리 (직원 `/employee/**`, 고객은 나머지를 각자 체인이 처리) → 2. 관리자 세션이 없으면 화면은 관리자 로그인 화면으로 이동, `/admin/api/**`는 401 (fetch가 로그인 화면 HTML을 받지 않도록. 팀원1 `SecurityConfig.java` 60줄에 설정 추가 필요, `ROLE-관리자·직원-권한정리.md` 6장 8번) → 3. 역할이 SUPER_ADMIN·OPERATOR·SERVICE가 아니면 403. 역할별 URL 제한은 AUT-004 (권한표는 `ROLE-관리자·직원-권한정리.md`, 확정 전) |
| 출력/결과 | 통과 시 요청 처리 |
| 예외 처리 | 고객·직원으로만 로그인한 상태로 접근 → 관리자 로그인 화면으로 이동 (영역마다 세션 키가 달라 로그인 안 된 것으로 봄) |
| 사후 조건 | 없음 |
| 관련 화면 | 403 오류 화면 |
| 관련 API | 관리자 API 전체 |
| 관련 테이블 | 없음 |
| 비고 | 영역 분리는 팀원1 `SecurityConfig`에 구현 완료 (팀 레포 `a6fa306`). 역할별 세부 제어(AUT-004)를 `SecurityConfig`에 넣을지 `@PreAuthorize`로 넣을지는 팀원1과 확인 필요. 관리자 체인은 `/admin/**`만 잡으므로 관리자 API는 `/admin/api/**`에 둔다 (공통 사항 참고). 401 설정은 실행해 보지 않음 — API를 처음 만들 때 팀원1에게 요청하고 테스트로 확인 |

| 예외 처리 | 다른 사람 알림 접근 → 403 (수신자 종류와 ID 둘 다 본인과 일치해야 함) |
| 사후 조건 | 읽음 처리 시 미확인 개수 감소 |
| 관련 화면 | 관리자 공통 헤더 알림 아이콘, 알림 목록 |
| 관련 API | `GET /admin/api/notifications?unread=&page=`, `PATCH /admin/api/notifications/{id}/read` |

| 비고 | WebSocket 알림을 놓쳐도 여기서 확인 가능. 로그인 직후 미확인 개수를 바로 표시 |

### 2.15 FUNC-ADM-ACT-005 직원 계정 발급

| 항목 | 내용 |
|---|---|
| 연결 요구사항 | FR-ADM-ACT-005 |
| 사용자/권한 | SUPER_ADMIN만 |
| 사전 조건 | 사용 중인 지점(`branch_type = 'BRANCH'`, `use_yn = 'Y'`)이 1개 이상 있음 |
| 입력 항목 | 이름(필수), 이메일(필수), 전화(선택), 소속 지점(필수), 직급(필수, 표시용), 역할(필수, STAFF/MANAGER), 입사일(필수), 생성 사유(필수, 200자, 예: 신규 입사). 사번·비밀번호는 입력하지 않음 |
| 처리 로직 | 1. 입력 검증 (이메일 중복, 지점이 사용 중인 BRANCH인지) → 2. 사번 자동 생성: 마지막 사번 숫자 +1, `E` + 4자리 (없으면 `E0001`) → 3. 임시 비밀번호 생성 후 BCrypt 해시 → 4. `Employee.builder()`로 만들어 `EmployeeRepository.save()` (`tempPassword = true`, 상태는 기본값 ACTIVE) → 5. `admin_log` 1건 (`EMPLOYEE_CREATE`, 대상 `EMPLOYEE`, 사번·역할, reason = 생성 사유). 2~5는 한 트랜잭션 |
| 출력/결과 | 임시 비밀번호 안내 모달(M-03)에 사번과 임시 비밀번호를 한 번만 표시 |
| 예외 처리 | 이메일 중복 → "이미 등록된 이메일입니다" / 지점이 ATM이거나 미사용 → "선택할 수 없는 지점입니다" / 사번 중복(동시 생성) → "잠시 후 다시 시도해 주세요" / SUPER_ADMIN 아님 → 403 |
| 사후 조건 | 새 직원은 사번 + 임시 비밀번호로 `/employee/login` 로그인 가능, 첫 로그인 때 비밀번호 변경 강제(팀원1) |
| 관련 화면 | S-19 계정 목록(직원 탭), S-20 계정 생성, M-03 임시 비밀번호 안내 |
| 관련 API | `GET /admin/employees/new`, `POST /admin/employees` (초안) |
| 관련 테이블 | employee(팀원1), branch(팀원1, 조회만), admin_log |
| 비고 | 회원가입이 아님. 팀 README 메뉴 14.13 "직원 계정 관리" 중 등록. 임시 비밀번호는 로그에 남기지 않는다. 마지막 사번 조회·이메일 중복 확인·지점 목록 조회를 어느 파일에 둘지 팀원1과 상의 (ROLE-관리자·직원-권한정리.md 6장 7번). 계획은 01-기획서 5.1 |
